### 프로젝트 4: 롯데카드 마이데이터 제공자 API Request 429 Status Error 개선

| 항목 | 내용                |
|---|-------------------|
| **기간** | 2023.06 - 2023.07 |
| **역할** | 설계 / 구현 / 운영      |
| **소속** | 롯데이노베이트            |

**배경 (Situation)**:
> 토스, 뱅크샐러드와 같은 마이데이터 서비스 플랫폼으로부터 롯데카드 자산연동 회원 정보에 대한 API요청을 받는 시각에 클러스터의 리소스가 한정되어 있어 '429' 상태 오류가 과도하게 발생하고, 클라이언트 측에서 불만을 제기하여 최적화 작업이 필요.

**목표 (Task)**:
> 429에러를 감소시켜 클라이언트의 원활한 정보 수집을 제공

**수행 내용 (Action)**:
- 마이데이터 제공자 업무의 아키텍처 설계를 분석하여, 클라이언트의 API 요청이 3scale(API Manager) 솔루션을 거쳐 End Point pod까지 어떻게 처리되는지 파악
- API 유량을 관리하는 3scale 관련 pod의 리소스를 조사
- CPU 사용률이 특정 시간에 100%에 도달하는 문제를 발견, 
- 메모리 증설을 시행. End Point pod의 리소스 상태를 모니터링하고, 클러스터 전체의 리소스를 고려하여 HPA(Horizontal Pod Autoscaler) 설정을 최적화
- 지속 적인 429 에러 발생으로 클라우드 외부 영역을 조사
- API 요청이 API 매니저로 도달하기 전, 마이데이터 제공자 클러스터 인바운드 서버를 거쳤음을 감안하고, 웹서버로 사용된 nginx의 work_process, connections 증설

**결과 (Result)**:
- [ ] 마이데이터 제공자 정기 수집 시간은 오전 11시에 30%에 달하던 429 Error를 10%로 감소시킴

**사용 기술**: OCP, Nginx, 3scale

### 프로젝트 5: LOCA 클러스터 리소스 낭비 개선

| 항목 | 내용                |
|---|-------------------|
| **기간** | 2023.05 - 2023.06 |
| **역할** | 구현 / 운영           |
| **소속** | 롯데이노베이트           |

**배경 (Situation)**:
> 클러스터 점검 중, 운영 노드 로그 파이프라인(fluentd) 데몬 파드가 비정상 상태임을 발견. 데몬 파드가 단순히 Pending 상태가 아니라, 컨테이너를 반복 생성 및 종료하며 재기동을 5만회 이상 시도하는 상황.

**목표 (Task)**:
> 반복 재기동을 방지하여 컴퓨팅 리소스 낭비 감소

**수행 내용 (Action)**:
- 먼저 현재 서비스에 영향을 미치는지 확인, 모니터링은 whatap 솔루션을 통해 이루어져 있어 영향 없음.
- 문제를 파악하기 위해 daemonSet 설정(yaml) 파일을 확인하여 컨테이너 생성 부분을 분석. 해당 daemonSet은 InitContainer를 사용하여 운영 ElasticSearch 파드와 통신 상태를 체크
- 문제는 운영 ElasticSearch 파드가 종료되어 있어서 발생.
- 현재 운영 중이지 않은 pod이므로 fluentd를 복구하는 것이 아닌, 데몬 자체를 기동하지 않도록 설정을 변경. 
- 각 노드에 기동 중인 fluentd 데몬의 수를 확인하고, 각 pod의 할당 메모리와 CPU 리소스를 분석하여 데몬 종료 시 확보되는 리소스를 계산.
- OCP에서는 데몬이 해당 노드에 지정된 nodeSelector 값과 일치해야 기동되기 때문에, yaml 파일의 nodeSelector 값을 임의로 변경하여 데몬을 종료.

**결과 (Result)**:
- [ ] 전체 운영 클러스터의 fluentd가 차지하는 리소스 모두를 확보 (4G mem, 4 Core)

**사용 기술**: OCP, Fluent, Elasticsearch

### 프로젝트 6: 마이데이터 사업자 자산/지출 리포트 API 개선 

| 항목 | 내용                |
|---|-------------------|
| **기간** | 2022.11 - 2022.12 |
| **역할** | 구현                |
| **소속** | 롯데이노베이트           |

**배경 (Situation)**:
> 마이데이터 사업자 자산/지출 리포트 PUSH 발송 시, 트래픽이 증가하면서 DB cpu가 100%에 도달하여 서버 다운 및 지연이 발생

**목표 (Task)**:
> 마이데이터 사업자 리포트 개선을 통해 운영 안정화

**수행 내용 (Action)**:
- 로그를 수집하여 API 호출 구조, DB 쿼리를 분석
- PUSH를 통한 고객 진입 시, 프론트에서 요구하는 객체 값을 조회하기 위해 불필요한 쿼리를 다수 남용하고 있었고, 쿼리에 인덱스가 걸려있지 않아 DB에 심한 부하를 발생
- 프론트에서 백엔드로 요청하는 API의 return VO를 정리하여 필수적인 항목만 조회하도록 VO 객체를 재정립
- 해당 VO 값을 채우기위한 최소한의 쿼리만 호출되도록 개선하였고, 쿼리에서 통계를 내는 부분을 DB에서 단순 조회를 통해 값을 리턴 받은 후, 백엔드 컨트롤러에서 메서드를 통해 통계를 생성하여 API를 리턴하도록 수정
- 인덱스가 걸려있지 않은 쿼리에 인덱스를 추가하여 프로세스를 최적화

**결과 (Result)**:
- [ ] 이후 PUSH 발송 시 DB CPU가 60~70% 정도로 약 10분간 유지 후 다시 안정화.

### 프로젝트 7: 마이데이터 사업자 자동차 보험 리워드 지급 API 개발

| 항목 | 내용                |
|---|-------------------|
| **기간** | 2022.05 - 2022.06 |
| **역할** | 개발                |
| **소속** | 롯데정보통신            |

**배경 (Situation)**:
> 롯데카드 마이데이터 고객 중 자동차 보험을 신규로 연동하는 고객에게 기프티샷을 지급하는는 이벤트 런칭

**목표 (Task)**:
> 해당 리워드를 기 지급받은 고객이 탈퇴 후 재가입 시 중복 지급이 되지 않아야 하는 조건으로 이벤트 API를 개발

**수행 내용 (Action)**:
- 마이데이터 자산 연동 시 해당 고객의 자산 정보가 적재되는 프로세스 전체를 확인.
- 자동차 보험 자산의 코드를 확인하여 고객 보험 자산 테이블에 해당 코드로 적재 시, 리워드 지급 API를 호출하도록 설계
- 이미 기 지급받은 고객의 경우 중복 지급을 방지하기 위하여 리워드 지급 이력 테이블에 마이데이터 고객 번호를 포함하여 롯데카드 고객 번호가 존재하는 경우, 해당 이벤트에 이미 참여하였음을 고지하는 알림 문구가 호출되도록 프로세스를 개발
- 프로젝트 구축 당시 보험 자산 정보 호출 API에서 보험 코드가 누락되는 결함이 발견
- 자산 연동 API를 호출하고 응답 값을 정리하는 과정에서, 조건절 String이 다르게 설정되어 null 값으로 리턴받는 상황을 수정.


**결과 (Result)**:
- [ ] 마이데이터 자동차 보험 자산신규 연동 고객에게 리워드를 정상 지급하였으며, 2023.12  마이데이터 사업자 2.0 프로젝트가 오픈하기 전까지 운영.

**사용 기술**: Java, BXM Framework, Spring, Mybatis
