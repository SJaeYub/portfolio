## 1. 업무 배경 및 목적 (Background & Purpose)

### 1.1 업무 개요

```
MSA 개발 환경(VPC-TST-MSA)에 인메모리 캐시 레이어가 필요하여 AWS ElastiCache Valkey를 신규 생성하였다.
기존 개발자들이 하드코딩 환경변수로 Redis 접속 정보를 관리하던 방식을 개선하여,
IRSA + AWS Secrets Manager + Secrets Store CSI Driver 기반의 보안 강화 연동 구조로 전환하였다.
```

### 1.2 업무 목적

- **해결하려는 문제 / 개선하려는 상황**: 접속 정보(host, port)를 yaml/ConfigMap에 평문으로 노출하는 보안 취약점 제거 및 중앙화된 시크릿 관리 체계 수립
- **성공 기준 (Definition of Done)**:
  - [x] Terraform으로 ElastiCache Valkey 클러스터 생성 완료
  - [x] AWS Secrets Manager에 Valkey host/port 등록 완료
  - [x] IRSA 구성 (IAM Role ↔ k8s ServiceAccount 바인딩) 완료
  - [x] SecretProviderClass 및 k8s Secret 객체 생성 완료
  - [x] 앱 컨테이너에서 Secret mount를 통한 Valkey 접속 확인

### 1.3 관련 배경 지식 / 시스템 설명

```
- 환경: Amazon EKS Fully Private Endpoint 구조 (외부 접근은 Bastion Host 경유)
- VPC: VPC-TST-MSA
  - EKS Worker Node 서브넷: SUB-TST-MSA-EKS-SVC-A
  - ElastiCache 서브넷: SUB-TST-MSA-EC2-SVC-A
- EKS와 ElastiCache는 동일 VPC 내 프라이빗 서브넷에 존재하므로 VPC 내부 라우팅으로 직접 통신 가능
- Pod ↔ Valkey 통신은 Bastion과 무관하며, AWS VPC CNI가 Pod에 VPC 네이티브 IP를 직접 부여하여 NAT 없이 통신
- ElastiCache는 AWS 관리형 인프라이나, 서브넷 그룹 설정을 통해 사용자 VPC에 ENI를 생성하여 프라이빗 IP로 접근 가능
- IRSA(IAM Roles for Service Accounts): EKS OIDC Provider를 통해 k8s ServiceAccount에 IAM Role을 연결하는 메커니즘
```

#### Step 3. IAM Role 및 IRSA 구성

**목적:** k8s ServiceAccount에 Secrets Manager 조회 권한을 가진 IAM Role 연결

```hcl
# IAM Role (OIDC 신뢰 정책 포함)
resource "aws_iam_role" "valkey_irsa" {
  name = "msa-dev-valkey-irsa-role"
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect = "Allow"
      Principal = {
        Federated = "arn:aws:iam::123456789:oidc-provider/oidc.eks.ap-northeast-2.amazonaws.com/id/XXXX"
      }
      Action = "sts:AssumeRoleWithWebIdentity"
      Condition = {
        StringEquals = {
          "oidc.eks.ap-northeast-2.amazonaws.com/id/XXXX:sub" = "system:serviceaccount:msa-dev:<앱 SA명>"
        }
      }
    }]
  })
}

# Secrets Manager 조회 권한 부여
resource "aws_iam_role_policy" "valkey_secret_policy" {
  role = aws_iam_role.valkey_irsa.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["secretsmanager:GetSecretValue", "secretsmanager:DescribeSecret"]
      Resource = aws_secretsmanager_secret.valkey.arn
    }]
  })
}
```

#### Step 4. k8s ServiceAccount 및 SecretProviderClass 생성

**목적:** IRSA 연동 ServiceAccount 생성 및 Secrets Manager → k8s Secret 동기화 정의

```yaml
# ServiceAccount
apiVersion: v1
kind: ServiceAccount
metadata:
  name: <앱 서비스 SA명>
  namespace: msa-dev
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::123456789:role/msa-dev-valkey-irsa-role
```

```yaml
# SecretProviderClass
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: valkey-secret-provider
  namespace: msa-dev
spec:
  provider: aws
  parameters:
    objects: |
      - objectName: "msa-dev/valkey/config"
        objectType: "secretsmanager"
        jmesPath:
          - path: REDIS_HOST
            objectAlias: redis_host
          - path: REDIS_PORT
            objectAlias: redis_port
  secretObjects:
    - secretName: valkey-secret
      type: Opaque
      data:
        - objectName: redis_host
          key: REDIS_HOST
        - objectName: redis_port
          key: REDIS_PORT
```

```yaml
      volumeMounts:
        - name: secrets-store
          mountPath: /mnt/secrets
          readOnly: true
      envFrom:
        - secretRef:
            name: valkey-secret
```

## 7. 기술 메모 (Technical Notes)

### 7.1 핵심 기술 포인트

```
1. AWS VPC CNI
   - EKS Pod는 오버레이 네트워크 없이 VPC 서브넷 IP를 직접 부여받음 (ipamd 데몬 관리)
   - veth pair로 Pod ↔ Node 연결, VPC 기본 라우팅으로 동일 VPC 내 서브넷 간 직접 통신
   - Pod ↔ Valkey 통신은 Bastion과 무관한 완전한 VPC 내부 경로

2. ElastiCache 네트워크 구조
   - AWS 관리 인프라이나 사용자 VPC 서브넷에 ENI를 생성하여 프라이빗 IP 부여
   - Pod 입장에서는 동일 VPC의 일반 서버와 통신하는 것과 동일한 경로

3. IRSA 동작 원리
   - EKS OIDC Provider → STS AssumeRoleWithWebIdentity → 임시 자격증명 발급
   - Pod 기동 시 aws-node가 OIDC 토큰을 /var/run/secrets/eks.amazonaws.com/serviceaccount/token에 자동 주입

4. Secrets Store CSI Driver 흐름
   - kubelet → CSI Driver → OIDC 토큰으로 IAM Role 가정 → Secrets Manager 조회
   - 조회된 값을 tmpfs(메모리 기반 파일시스템)에 마운트하여 컨테이너에 노출
   - secretObjects 설정으로 k8s Secret 객체로도 동기화 가능

5. Fully Private EKS 환경 주의사항
   - Secrets Manager VPC Endpoint(com.amazonaws.region.secretsmanager) 필요
   - 없을 경우 CSI Driver가 인터넷 없이 Secrets Manager에 접근 불가
```
